# Версия приложения

Для каждого готового обновления повышайте номер версии в `mailclient/__init__.py` по SemVer: исправления — patch, новые возможности — minor.
Синхронно обновляйте строковые и числовые версии в `tools/windows-version.txt` перед сборкой EXE.
Заголовок главного окна, окно «О программе» и `QApplication.applicationVersion()` должны использовать `mailclient.__version__`.

# База данных до релиза

Миграций базы в коде программы нет и не добавляйте их (никаких ALTER TABLE, дозаполнений старых записей и проверок «база от прошлой версии»). Схема описывается только в `SCHEMA` / `FTS_SCHEMA` в `mailclient/db.py`.
Номер схемы — `SCHEMA_VERSION` в `mailclient/db.py` (хранится в `PRAGMA user_version`). Программа открывает только базу своей схемы; базу другой схемы не меняет, а сообщает, что её нужно обновить (`SchemaMismatch`).
Если изменение схемы затрагивает существующую базу:
- увеличьте `SCHEMA_VERSION`;
- опишите переход в `tools/migrate_db.py` (функция `migrate` и `FROM_VERSION`). Скрипт не входит в программу и установщик; в нём только один, последний переход;
- скрипт запускают при закрытой программе: сначала `--dry-run` (на копии), затем по-настоящему (резервная копия делается сама);
- когда база обновлена, переход из скрипта удаляют (`FROM_VERSION = None`, `migrate` пустая).
