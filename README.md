# SimpleMail

Простой почтовый клиент на Python + Qt (PySide6). Почта хранится локально: список и текст писем — в SQLite, полные копии скачанных писем с вложениями — в файлах `.eml` в папке ящика.

## Что умеет

- Несколько почтовых ящиков (IMAP для приёма, SMTP для отправки). Для Gmail / Googlemail, Яндекса (включая `.com` и `.by`), Mail.ru, Rambler, Outlook / Hotmail / Live / MSN серверы подставляются сами по адресу. Нестандартные порты сохраняются при смене шифрования.
- Gmail: вход через Google в браузере (OAuth2, без пароля приложения) или пароль приложения; понятная подсказка, если Google не принимает обычный пароль. Нужен Client ID приложения Google, который можно один раз встроить в сборку; настройка описана ниже.
- Microsoft 365 / Outlook: OAuth2 с входом по коду устройства, автоматическим обновлением токенов и защищённым локальным кешем. Требуется Client ID собственного приложения Microsoft Entra; настройка описана ниже.
- Порядок ящиков меняется перетаскиванием в главном дереве или в окне «Почтовые ящики», а также кнопками «Вверх»/«Вниз» (`Ctrl+↑` / `Ctrl+↓`) в этом окне; порядок сохраняется после перезапуска.
- Входящие, Спам, Отправленные, Корзина, локальные Черновики и Исходящие; остальные серверные папки появляются в дереве после проверки.
- Спам-фильтр:
  1. белый список (точный адрес / точный домен / вхождение в отправителе, теме или тексте) — никогда не спам;
  2. чёрный список — всегда спам;
  3. если сервер поставил `X-Spam-Flag: YES` — спам;
  4. байесовский фильтр, который учится на кнопках «Спам» / «Не спам» (включается после 5 писем каждого вида).
  Почему письмо попало в спам — видно в подсказке к строке и в заголовке письма. Автоспам перемещается в серверную папку Junk, если сервер поддерживает безопасное перемещение; при ошибке сохраняется локально, причина показывается пользователю.
- Редактор письма с оформлением (шрифты, цвета, списки, таблицы, картинки, ссылки) или обычный текст; несколько подписей (Настройки → Подписи), у каждого ящика своя подпись по умолчанию, в окне письма её можно сменить.
- Переписка в окне письма (кнопка «Переписка (N)» в шапке письма, «Вид → Показывать переписку», `Ctrl+T`): все письма цепочки по времени — входящие и ваши ответы из «Отправленных», из всех папок и ящиков. Письма связываются по заголовкам In-Reply-To / References, а если почтовая программа собеседника их не ставит — по теме без «Re:»/«Fwd:» с общим собеседником. Открытое письмо выделено, страница прокручена к нему; каждое письмо сворачивается щелчком по шапке, «Свернуть все, кроме этого» / «Развернуть все» — вверху страницы. Цитаты предыдущих писем свёрнуты в кнопку «•••». Черновики, корзина и спам в переписку не попадают. При первом запуске версии 0.14 заголовки уже скачанных писем разбираются один раз в фоне.
- Ответить, ответить всем, переслать, перенаправить, быстрый ответ; вложения. В полном редакторе ответы и пересылки сохраняют оформление исходного письма и встроенные CID-картинки; внешние ресурсы из цитаты удаляются.
- Раскладки окна (Вид → Раскладка окна): классическая, «письмо справа», только список. Колонки списка настраиваются (правый клик по заголовку), сортировка кликом; вид окна запоминается.
- Фоновый поиск по отправителю, получателю, теме, тексту письма и именам вложений: в папке, ящике или во всех ящиках, с фильтром дат и непрочитанных. `Ctrl+Shift+F` — поиск по всем ящикам. Результаты загружаются порциями по 500, кнопка «Показать ещё» открывает следующую порцию.
- Синхронизация серверных папок и прочтения, IMAP IDLE для входящих, резервная проверка по таймеру, F5 — проверить сейчас.
- Флажки «Важное» синхронизируются с сервером; доступны скрытые копии Bcc, остановка проверки, журнал ошибок, значок в трее с уведомлениями, поиск FTS5 и ускоренная проверка CONDSTORE.
- Автоопределение проверяет пароль только через SSL/TLS или STARTTLS; найденные соединения без шифрования показываются для ручного выбора без отправки пароля.
- Автосохранение черновиков и быстрых ответов, постоянная очередь исходящих, полная загрузка истории с паузой и продолжением, резервное копирование и восстановление.
- HTML-письма показываются встроенным браузером без зависаний; картинки из интернета загружаются только по кнопке «Показать картинки» (защита от слежки); выбор запоминается для письма, в том числе после перезапуска. JavaScript выключен. Если Qt WebEngine недоступен, запасной просмотрщик показывает текст и встроенные растровые картинки, блокируя внешние ресурсы и локальные файлы.
- Светлая и тёмная темы автоматически следуют настройке системы и переключаются без перезапуска, включая просмотр писем, значки и окна настроек.

## Установка (Windows)

1. Установите Python 3.11+ с python.org (галочка «Add python.exe to PATH»).
2. В папке программы:
   ```
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   python main.py
   ```
3. При первом запуске откроется окно «Почтовые ящики» — добавьте ящик.

> Для Gmail, Яндекса и Mail.ru нужен **пароль приложения** (создаётся в настройках безопасности аккаунта), обычный пароль не подойдёт. В Яндексе также включите доступ по IMAP в настройках почты.

Пароли хранятся в системном хранилище Windows (Диспетчер учётных данных) через `keyring`. Если оно недоступно, пароль сохраняется в базе открытым текстом.

## Gmail: вход через Google

Обычный пароль Google в почтовых программах не работает: сервер отвечает «Application-specific password required». Есть два способа.

**Вход через Google (рекомендуется).** В настройках ящика выберите способ входа «Google (вход в браузере)» и нажмите «Войти в Google…». Откроется браузер: войдите в нужный аккаунт и разрешите доступ к почте. Пароль в SimpleMail не вводится. Токен обновляется автоматически и хранится, как у Microsoft, в `%LOCALAPPDATA%\SimpleMail\OAuth` под защитой Windows DPAPI. Для адресов `@gmail.com` этот способ выбирается сам, если Client ID уже известен программе.

Для этого нужен Client ID приложения Google. Его регистрируют один раз:

1. Откройте [Google Cloud Console](https://console.cloud.google.com/), создайте проект и включите **Gmail API** (APIs & Services → Library).
2. **Google Auth Platform → Get started**: название (например, SimpleMail), e-mail поддержки, тип аудитории External. Пока приложение в статусе Testing, добавьте адреса пользователей в **Audience → Test users**. Для постоянной работы нажмите **Publish app**: в статусе Testing Google отзывает вход через 7 дней.
3. **Data Access → Add or remove scopes**: добавьте `https://mail.google.com/`.
4. **Clients → Create client**: тип **Desktop app**, затем **Download JSON**. Для настольных приложений Client secret не является секретом в обычном смысле: Google сам указывает, что его нельзя защитить в установленной программе. Вход идёт через системный браузер с адресом возврата `http://127.0.0.1:<порт>` и PKCE.

**Встроить ключи в программу** (тогда пользователям ничего не настраивать: поля Client ID скрыты, остаётся кнопка «Войти в Google…», а для новых ящиков `@gmail.com` вход через Google выбирается сам):

- запуск из исходников: `python tools/oauth_clients.py client_secret_XXXX.json` — записывает `mailclient/oauth_clients.json` (файл не хранится в git);
- установщик из GitHub Actions: добавьте секреты репозитория **Settings → Secrets and variables → Actions** `SIMPLEMAIL_GOOGLE_CLIENT_ID` и `SIMPLEMAIL_GOOGLE_CLIENT_SECRET` (для Microsoft — `SIMPLEMAIL_MICROSOFT_CLIENT_ID`); `tools/build_windows.ps1` подставит их в сборку.

Без встроенных ключей Client ID и Client secret можно вставить в настройках ящика; они запоминаются для следующих ящиков Gmail. При встроенных ключах свои можно указать по ссылке «Свой Client ID…».

У непроверенного Google приложения при входе показывается предупреждение «Google hasn't verified this app» (продолжить: «Advanced» → «Go to SimpleMail»), и им могут пользоваться до 100 аккаунтов. Для большего числа пользователей нужна проверка приложения Google.

Антивирусы с проверкой зашифрованных соединений (например, Kaspersky для `imap.gmail.com`) иногда задерживают первое подключение. SimpleMail один раз автоматически повторяет его. Если таймаут повторяется, программа называет антивирус: добавьте SimpleMail в его доверенные программы с параметром «Не проверять зашифрованный трафик».

**Пароль приложения.** Если вход через Google не настроен, создайте [пароль приложения](https://myaccount.google.com/apppasswords) (нужна двухэтапная проверка) и введите его вместо обычного пароля. Ссылка показывается в настройках ящика для адресов Gmail.

## Microsoft 365 / Outlook: OAuth2

Для входа нужен **Application (client) ID** зарегистрированного приложения Microsoft Entra. SimpleMail — настольное публичное приложение: **Client Secret не нужен** и в программу не вводится.

1. Откройте [Microsoft Entra → App registrations](https://entra.microsoft.com/), создайте регистрацию приложения. Для личных Outlook и рабочих аккаунтов выберите поддержку аккаунтов любой организации и личных Microsoft accounts.
2. В разделе **Authentication → Advanced settings** включите **Allow public client flows**. Для входа по коду устройства Redirect URI не требуется.
3. В **API permissions → Add a permission → APIs my organization uses → Office 365 Exchange Online → Delegated permissions** добавьте `IMAP.AccessAsUser.All` и `SMTP.Send`. Это разрешения Exchange Online, не Microsoft Graph. Если политика организации требует согласия администратора, его должен предоставить администратор.
4. Скопируйте **Application (client) ID** из Overview. В SimpleMail откройте «Настройки → Почтовые ящики», выберите способ входа **Microsoft OAuth2**, вставьте Client ID. Tenant `common` подходит для личных и рабочих аккаунтов; для регистрации только своей организации укажите её tenant ID.
5. Укажите полный адрес почты как логин, IMAP `outlook.office365.com:993` с SSL/TLS и SMTP `smtp.office365.com:587` с STARTTLS. Нажмите «Войти в Microsoft…», откройте предложенную страницу, введите код и подтвердите разрешения. Затем сохраните настройки ящика.

IMAP и SMTP AUTH должны быть разрешены для ящика; корпоративная политика может запрещать SMTP AUTH или вход по коду устройства даже при корректной регистрации. Проверка подключения показывает результат для каждого протокола. Официальная документация: [OAuth для IMAP и SMTP](https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth), [вход по коду устройства](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code).

Токены обновляются автоматически и хранятся отдельно от базы в `%LOCALAPPDATA%\SimpleMail\OAuth`, с шифрованием Windows DPAPI для текущего пользователя. При недоступности защищённого хранилища токены остаются только в памяти: после перезапуска потребуется повторный вход, о чём программа сообщает. Токены не входят в резервные копии; на другом компьютере войдите заново. Кнопка «Выйти из Microsoft» удаляет локальный сеанс SimpleMail.

## Где хранится почта

- **Копии писем и вручную сохранённые вложения** — в папке хранения ящика (задаётся в настройках ящика, по умолчанию `Документы\SimpleMail\<адрес>`):
  - `Входящие\ГГГГ-ММ\*.eml`, `Отправленные\ГГГГ-ММ\*.eml` — письма целиком (с вложениями), открываются любым почтовым клиентом;
  - `Вложения\` — папка, которая предлагается по умолчанию при ручном сохранении вложений.
  При смене папки программа предложит перенести уже скачанные письма.
- **Список и текст писем, имена вложений, настройки, правила спама** — `%APPDATA%\SimpleMail\mail.db`. Другая папка базы: `python main.py --data D:\Mail`.

**Содержимое новых вложений хранится один раз — внутри `.eml`.** Это выбранный способ хранения без дублирования файлов в SQLite. В базе сохраняются имена и порядок вложений для списка и поиска; при открытии или сохранении содержимое извлекается из локального письма. Отдельный файл в папке `Вложения` появляется только при ручном сохранении.

Для работы без интернета сохраняйте **и `mail.db`, и папки ящиков с `.eml`**. Если файл письма удалён или недоступен, сохранённые в базе текст письма и имена вложений остаются, но открыть или сохранить новые вложения без исходного `.eml` нельзя. Встроенное резервное копирование включает и базу, и папки ящиков.

Исключения: черновики и исходящие хранятся в SQLite целиком, вместе с вложениями. Сохранившиеся копии вложений из версий 0.8–0.9 также могут читаться из базы при недоступности `.eml`. Эта совместимость относится только к ранее сохранённым копиям. Старые копии не удаляются автоматически. Одноразовых преобразований старых вложений в программе нет.

При удалении ящика скачанные `.eml` по умолчанию остаются на диске. Для очистки поставьте отдельную галочку в окне подтверждения: удаляются только отслеживаемые программой `.eml` внутри папки этого ящика, которые не используются другими ящиками. Вручную сохранённые вложения, посторонние файлы и сама папка остаются.

Встроенные картинки находятся внутри самого письма; внешние картинки и ссылки требуют интернета. При первой проверке ящика сначала скачиваются последние 300 писем каждой папки, чтобы почтой можно было пользоваться сразу. Если на сервере есть более старые письма, программа сообщает их число и предлагает скачать все. «Не сейчас» откладывает вопрос до следующего запуска, галочка «Больше не спрашивать» отключает его совсем. Скачать остальные письма можно и позже: правая кнопка мыши на ящике → «Скачать остальные письма (скачано X из Y)» (пункт есть, пока скачано не всё), отметка «Скачивать все письма с сервера» в настройках ящика или «Файл → Скачать всю историю» для всех ящиков. Во время загрузки полоса в строке состояния показывает «загружено / всего», рядом — папка и оставшееся время.

## История и синхронизация

«Файл → Скачать всю историю» загружает все доступные письма всех серверных папок включённых ящиков. Состояние загрузки показывается в строке статуса. «Приостановить загрузку истории» останавливает её после текущего сетевого запроса; уже скачанное сохраняется. Повторный запуск команды продолжает с недостающих писем. После обрыва соединения незавершённая загрузка продолжается при следующей проверке почты.

Прочтение с телефона обновляется при проверке; изменения прочтения, сделанные без сети в SimpleMail, отправляются на сервер при подключении. Перемещение другим клиентом отражается в серверных папках. Если письмо удалено с сервера или изменилось поколение UID, прежняя локальная копия сохраняется в «Локальном архиве». IDLE ускоряет обновление входящих; остальные папки проверяются по таймеру и F5.

IDLE реагирует на новые письма, изменения флагов (`FETCH`) и удаления (`EXPUNGE`). При переносе письма из Junk во Входящие другим клиентом локальная пометка спама снимается при синхронизации. IMAP использует `UTF8=ACCEPT`, если сервер разрешает `ENABLE`, с сохранением идентичности локальных папок при смене кодировки. Для не-ASCII логинов и паролей SMTP выбирает поддерживаемый сервером PLAIN или LOGIN.

В Gmail одно письмо может лежать в нескольких «папках»-ярлыках. «Вся почта», «Важное» и «Помеченные» только повторяют письма из других папок, поэтому они не загружаются, а копии, скачанные прежними версиями, удаляются из программы (на сервере всё остаётся). Учтите: письма, которые в Gmail только заархивированы и не лежат ни в одной папке, видны лишь в «Вся почта». Префиксы `[Gmail]/` и `INBOX.` в названиях папок скрыты, серверные «Черновики» показываются как «Черновики на сервере» и только если в них есть письма.

## Правила спама и вложения

В «Настройки → Спам-фильтр» тип «Адрес отправителя (точно)» сопоставляет реальный адрес, а не отображаемое имя; «Домен отправителя (точно)» сопоставляет только указанный домен (`example.com` не включает `sub.example.com`). Белые правила проверяются первыми. Старые правила «Отправитель», «Тема» и «Текст письма» продолжают искать вхождение строки. Автоматическое перемещение в Junk не обучает байесовский фильтр повторно.

Открываемые вложения получают отдельные временные папки, поэтому одноимённые файлы разных писем не перезаписывают друг друга. Перед открытием исполняемых файлов и активных документов HTML/SVG требуется подтверждение.

## Черновики и исходящие

Текст, адресаты, оформление, встроенные картинки и вложения сохраняются в SQLite после изменения с задержкой около секунды и при закрытии окна. Быстрый ответ также сохраняется при смене письма. Открыть черновик или исходящее для редактирования можно двойным щелчком либо `Ctrl+O`. «Удалить черновик» явно удаляет сохранённый вариант.

«Отправить» сначала сохраняет письмо в постоянной очереди. При отсутствии соединения оно остаётся в «Исходящих» и повторяется при проверке включённого ящика. Если результат SMTP неизвестен или часть адресатов отклонена, автоматического повтора нет: состояние видно в списке, перед ручной повторной отправкой требуется подтверждение. Для одной базы допускается один процесс SimpleMail.

После успешного SMTP письмо сохраняется в серверной папке Sent. Если сохранение копии не удалось, повторяется только этот шаг, без повторной SMTP-отправки. Существующая серверная копия проверяется по Message-ID и содержимому. Старые локальные отправленные письма автоматически на сервер не загружаются.

## Адресная книга и подсказки адресов

В полях «Кому», «Копия» и «Скрытая» при вводе появляются подсказки: совпадение с началом имени, фамилии или любой частью адреса. `Enter` или `Tab` подставляет выбранный адрес как «Имя <адрес>» и ставит запятую для следующего. Уже указанные в поле адреса не подсказываются. Выше в списке те, кому вы писали сами, затем недавние.

Адресная книга (`Ctrl+Shift+B`, «Файл → Адресная книга…», кнопка «Адреса» в окне письма) заполняется сама: адресаты отправленных писем (включая скрытые копии) и отправители входящих. Спам, корзина и служебные адреса (`noreply`, `mailer-daemon`, `notifications` и т. п.) не добавляются; «Это спам» убирает отправителя, если вы ему не писали. При первом запуске версии 0.13 книга один раз собирается в фоне из уже скачанных писем.

Контакты можно добавить, изменить (имя, исправленное вручную, больше не меняется по письмам) и удалить. Удалённый адрес сам не возвращается по входящим письмам — только если вы снова напишете на него или добавите вручную. Из окна письма выбранные контакты добавляются кнопками «Кому», «Копия», «Скрытая»; из главного окна — «Написать письмо».

## Резервная копия и восстановление

«Файл → Создать резервную копию…» создаёт архив `.smbak` с согласованным снимком SQLite и файлами папок ящиков, включая вручную сохранённые вложения. Копию можно делать из открытой программы.

«Файл → Восстановить резервную копию…» проверяет архив, распаковывает его в отдельную папку и создаёт страховочную копию текущих данных `before-restore-*.smbak` рядом с рабочей базой. После перезапуска устанавливается подготовленная база; исходные папки до восстановления сохраняются. Восстановленные исходящие требуют проверки доставки перед повторной отправкой, чтобы старый архив не вызвал повторную рассылку. Пароли из системного хранилища Windows в архив не экспортируются; при переносе на другой компьютер их потребуется указать заново.

Пароли из резервного хранения в SQLite и токены OAuth также исключаются из копии. Перед распаковкой проверяются пути, свободное место и лимиты: до 200 000 записей архива и 100 ГиБ распакованных данных, с резервом 256 МиБ свободного места. Нарушение лимитов или повреждённый архив не заменяют текущую базу.

## Ограничения текущей версии

- При первой обычной проверке загружаются последние 300 писем каждой папки (настройка `initial_fetch_limit`); остальное доступно через загрузку полной истории.
- Кнопки «Спам» / «Не спам» перемещают письмо в обнаруженную серверную папку Junk и обратно. Если такой папки нет, спам отделяется локально.
- Удаление перемещает письмо в серверную корзину; локальная копия и вложения сохраняются. `Ctrl+Z` отменяет последнее удаление. В корзине доступно «Восстановить из корзины» (`Ctrl+Shift+Z`), в том числе после перезапуска.
- Безопасное перемещение требует IMAP MOVE или UIDPLUS. При отсутствии поддержки либо ошибке сервера письмо остаётся в локальном списке с сообщением об ошибке. Окончательное удаление из серверной корзины требует UIDPLUS и отдельного подтверждения; удаляются только выбранные UID.
- POP3 пока нет.

## Автоматическое получение почты

При запуске SimpleMail сразу проверяет включённые ящики. Если сервер поддерживает IMAP IDLE, программа держит отдельное фоновое соединение с INBOX и загружает новые письма по уведомлению сервера. После потери сети соединение восстанавливается автоматически; письма, пришедшие за время обрыва, проверяются при переподключении. Ожидание продлевается каждые 4 минуты (если соединение проверяет антивирус, например Kaspersky для Gmail, — каждую минуту), чтобы роутер или сетевой экран не оборвал молчащее соединение; после каждого продления программа сверяет число писем во «Входящих» (STATUS), поэтому новое письмо находится, даже если уведомление сервера задержал антивирус. Оборванное соединение обнаруживается за минуту.

Проверка по таймеру остаётся резервным способом, а для серверов без IDLE — основным. Интервал задаётся в «Настройки → Автопроверка почты» (по умолчанию 10 минут). Значение 0 отключает только таймер: IDLE продолжает работать. Для получения уведомлений программа должна быть запущена.

## Язык интерфейса

В меню «Настройки → Язык интерфейса» доступны русский и **Srpski (latinica)**. Выбор сохраняется в настройках и применяется при следующем запуске SimpleMail. Перевод охватывает меню, окна настроек, редактор писем, уведомления и стандартные диалоги Qt. Содержимое писем, названия подписей и существующие папки хранения не переводятся.

## Порядок почтовых ящиков

Откройте «Настройки → Почтовые ящики». Перетащите ящик в списке либо выделите его и нажмите «Вверх» / «Вниз». Порядок сохраняется сразу, отображается в главном окне и остаётся после перезапуска. Новые ящики добавляются в конец списка.

В главном окне также можно нажать правой кнопкой мыши на название ящика и выбрать «Вверх» или «Вниз».

Это же меню позволяет проверить выбранный ящик, написать с него письмо, открыть «Настройки ящика…» и включить или отключить его проверку. В подменю «Настройки» доступны управление ящиками, подписи, спам-фильтр, интервал автопроверки и язык интерфейса.

## Значок и автозапуск Windows

У приложения собственная иконка окна и панели задач. Исходник: `mailclient/icons/simplemail.svg`; PNG и ICO для Windows пересобираются командой `python tools/build_app_icon.py`.

Включите «Настройки → Запускать при входе в Windows», чтобы SimpleMail запускался после входа в вашу учётную запись Windows. Эту же галочку можно снять для отключения автозапуска. Используется настройка только текущего пользователя; сохраняется путь к текущей базе писем, в том числе при запуске с `--data`. Пункт доступен также в подменю «Настройки» по правому клику на ящике.

## Готовое приложение Windows (EXE)

Запуск: `dist\SimpleMail\SimpleMail.exe`. Python на компьютере для запуска этой сборки не нужен. Сохраняйте всю папку `SimpleMail` вместе с подпапкой `_internal`; один EXE отдельно от неё не переносите. Существующая база писем и настройки используются из прежнего расположения `%APPDATA%\SimpleMail`.

Повторная сборка: закройте собранное приложение и запустите `powershell -File tools\build_windows.ps1`. Сборочные зависимости перечислены отдельно в `requirements-build.txt`; настройки упаковки находятся в `SimpleMail.spec`. В собранной версии автозапуск указывает на EXE и сохраняет текущий путь `--data`.

## Установщик Windows и обновления (0.14.0)

Для передачи коллегам используйте **`dist\installer\SimpleMail-Setup-0.14.0-x64.exe`**. Это один файл, включающий Python, Qt и просмотр HTML-писем. Поддерживается 64-разрядная Windows 10 (1809+) / Windows 11. Программа устанавливается для всех пользователей, по умолчанию в `C:\Program Files\SimpleMail`; установщик запрашивает права администратора. Создаётся ярлык в меню «Пуск», ярлык на рабочем столе — по желанию.

Если раньше SimpleMail был установлен для текущего пользователя в `%LOCALAPPDATA%\Programs\SimpleMail` (версии 0.10–0.11.0), новая версия ставится в Program Files, а старая копия удаляется после успешной установки. Путь к почте (`--data`) и автозапуск переносятся на новую копию. Это работает, когда права администратора подтверждает тот же пользователь, который пользуется почтой; при вводе пароля другой учётной записи старую копию удалите вручную через «Приложения».

Почта, настройки и пароли используются из прежних мест. При обновлении и удалении программы они не удаляются. Перед первой установкой закройте переносную копию; далее запускайте установленную. Если автозапуск ранее указывал на переносную EXE, выключите и снова включите «Настройки → Запускать при входе в Windows» в установленной программе.

В **«Справка → Обновления…»** можно проверить новую версию, скачать её с индикатором прогресса, отменить загрузку и установить. Проверка при запуске включена по умолчанию для собранной Windows-версии; её можно отключить в настройках. Программа ничего не устанавливает без подтверждения пользователя. Перед установкой завершаются почтовые операции и сохраняются черновики, SimpleMail закрывается; мастер установки предлагает запустить его снова. Текущая папка приложения, язык и путь `--data` передаются установщику; при установке Windows запросит права администратора. Нельзя установить старую версию поверх новой.

Источник — только опубликованные стабильные релизы [TimohovAS/SimpleMail](https://github.com/TimohovAS/SimpleMail/releases). Загрузка идёт по HTTPS, размер и SHA-256 проверяются по данным GitHub перед сохранением и ещё раз перед запуском. При ошибке или обрыве загрузки установка не выполняется. Установщики кешируются в `%LOCALAPPDATA%\SimpleMail\Updates`, старые удаляются после успешной загрузки следующего. При отсутствии опубликованных релизов проверка сообщает, что новых обновлений нет. В исходной Python-версии автоматическая проверка и установка отключены, ручная проверка и скачивание доступны.

### Сборка установщика

1. Установите зависимости проекта в `.venv` и [Inno Setup 6.5+](https://jrsoftware.org/isdl.php).
2. Запустите `powershell -File tools\build_installer.ps1`. Отдельная сборка в `dist\installer-build` позволяет не заменять работающую переносную копию.
3. Результат: `dist\installer\SimpleMail-Setup-<версия>-x64.exe` и `SHA256SUMS.txt`.

Путь к компилятору можно передать через `-IsccPath` или `ISCC_PATH`. `-SkipBuild` повторно упаковывает уже готовую сборку из `dist\installer-build`, проверяя версию EXE. Обе сборочные команды проверяют согласованность `mailclient.__version__` и строковых/числовых версий `tools/windows-version.txt` через `tools/check_version.py`.

Проверка готовой сборки: `powershell -File tools\test_installer.ps1`. Сценарий использует отдельный идентификатор установки, ярлык, запись автозапуска и базу в `build\installer-validation`. Проверяются запуск EXE, обновление через помощника с ожиданием завершения прежнего процесса, путь почты с пробелами и `&`, отказ при откате, удаление автозапуска с кавычками и без них, сохранение тестовой почты. Эта же проверка выполняется в CI перед публикацией артефакта. Перед проверкой закройте собранные копии SimpleMail: они используют общий защитный mutex.

Помощник обновления копируется в кеш, ожидает завершения процесса SimpleMail и повторно проверяет размер и SHA-256 установщика. При ошибке появляется сообщение, подробности сохраняются в `install-*.error.log` в кеше обновлений. Закрытие окна обновлений отменяет текущую операцию; её запоздавшие результаты игнорируются.

### Публикация обновлений

1. Повышайте версию по SemVer и синхронно обновляйте `tools/windows-version.txt`. Исправления — patch, новые возможности — minor.
2. После проверки изменений создайте и отправьте тег `v<версия>` из нужного коммита. Workflow `Windows installer` запускает тесты, собирает установщик и создаёт **черновик** GitHub Release с EXE и контрольной суммой. Ручной запуск workflow собирает артефакт без публикации.
3. Проверьте установщик на отдельном компьютере, отредактируйте описание и опубликуйте стабильный релиз как Latest. Только после публикации приложения коллег увидят обновление. GitHub вычисляет SHA-256 для загруженного EXE; клиент требует этот digest и точное имя `SimpleMail-Setup-<версия>-x64.exe`.

Первая установка версии с механизмом обновления выполняется вручную. Для публикации с локального компьютера можно создать черновик релиза на GitHub и приложить те же два файла.

### Подпись Authenticode

Для подписанного выпуска нужен доверенный сертификат подписи кода с закрытым ключом в хранилище Windows текущего пользователя или компьютера и Windows SDK SignTool. Передайте `-CertificateThumbprint <отпечаток>` в `tools/build_installer.ps1` либо задайте `SIMPLEMAIL_SIGN_CERT_THUMBPRINT`. Путь к SignTool можно указать через `SIGNTOOL_PATH`; сервер меток времени — через `-TimestampUrl` или `SIMPLEMAIL_TIMESTAMP_URL` (по умолчанию `http://timestamp.digicert.com`).

Сначала подписывается приложение, затем Inno Setup подписывает установщик, деинсталлятор и временные копии Setup. Используются SHA-256 и метка времени RFC 3161; после подписи проверяется доверие Windows. Контрольная сумма установщика вычисляется после подписи. Если сертификат задан, ошибка подписи прерывает сборку. Без сертификата создаётся неподписанный установщик; сборочный сценарий не создаёт самоподписанный сертификат. В CI сертификат и закрытый ключ должны быть предоставлены отдельно через защищённое хранилище, затем сборка использует те же переменные окружения.
